Exemple : la revue du pipeline (chaque affirmation confrontée au code) a trouvé un défaut du code lui-même — un protocole refusé puis réécrit n'était jamais relu : 36 pistes remontaient, 33 avaient une revue REFUSE plus ancienne que le protocole actuel. Correctif : revue_acquise() n'accepte qu'une revue ACCEPTE postérieure au protocole ; témoin 23/23 ; effet vérifié le 2026-10-02. Autres gestes de la maintenance, tous nés d'incidents : le 2026-10-02 un CLI absent a produit 25 faux abandons en une minute, d'où la sonde avant tout départ (absent : rien ne part, aucun abandon compté) ; un superviseur qui relance sans fin masque la panne, d'où la borne de 3 relances par heure — et il le dit ; l'agent réparateur reçoit une COPIE des fichiers dans un bac, car son raccourci naturel serait de fabriquer la preuve manquante. Limite : le 26 septembre, quatre défauts sont venus de corrections (une porte trop large a refusé seize protocoles justes) ; on rejoue donc tous les témoins (étape P11).

Une mémoire qui nomme, et la preuve

Le cahier de bord : l'échec d'hier devient la consigne de demain, et rien n'est cru sans preuve.

LE PROBLÈME

Chaque session repart de zéro. Dans nos essais, la mémoire native n'a rien restitué d'une session à l'autre.

AVANTMémoire native du produit
session 1 : « mémorise cette couleur »
→ il bricole un fichier de notes
session 2 : « quelle est la couleur ? »
→ il ne retrouve rien
Le substitut échoue : la session suivante l'ignore
APRÈSBoucle fermée par le script
le script note la réponse du modèle
et NOMME le défaut :
« du texte autour du JSON »
il l'écrit en tête du prochain run :
« Ne le reproduis pas. »
Le défaut nommé devient la mémoire du run suivant
0/12 → 5/12

tâches réussies sans, puis avec la boucle fermée (rejeu strict). Le premier relevé, 6/8, était optimiste : elle améliore sans garantir.

Mesuré sur un seul modèle, au terminal, parfois à N=5 : chaque levier se rejoue sur votre terrain avant d'être cru.

[≈ 3 min] Message : la mémoire, ici, est un fichier que le code écrit et que le run suivant lit — pas une fonction du produit : dans nos essais la mémoire native n'a rien restitué d'une session à l'autre. Boucle fermée (CHAIN-121, claude-haiku-4.5, tâche « rendre un JSON nu ») : le script de contrôle nomme le défaut (« tu as ajouté du texte autour du JSON ») et l'écrit en tête de la consigne suivante. Premier relevé 6 sur 8 contre 0 sur 8 ; rejeu en alternance stricte : 5 sur 12 contre 0 sur 12. L'effet est reproduit mais de moitié : elle améliore sans garantir (deux séries sur quatre retombent à la troisième itération). Autour de cette boucle, la chaîne de mémoire du labo : preuve, niveaux, registre, carte, vues — gardée par des contrôles qui se testent eux-mêmes (--autotest) : « une ligne récente mais fausse ment mieux qu'une ligne vieille ». 639 décisions journalisées, une par fichier. Clôture : récapitulez les dix niveaux en suivant la pile, puis rappelez les bornes — un seul modèle, le terminal, parfois N=5 : tout se rejoue sur votre terrain.
